# 사진 한 장 → 게임 표정 시트

기본 출력은 **2560×960 투명 PNG**, **512×960 동일 셀 5개**, 순서는 **neutral / happy / angry / surprised / crying**이다.

얼굴 크기는 성별·머리카락 실루엣이 아니라 **neutral의 눈 중심선부터 턱끝까지 거리**로 맞춘다. 양쪽 눈 중심 거리도 보조 비교한다. 셀 여백과 게임 적용 크기는 별도로 정한다.

## 입력 역할

- 인물 사진 한 장이 정체성 기준이다. 사진 없이 시트만 주어졌으면 그 시트를 원본 인물 사진으로 간주하지 않는다. 인물의 이름은 추측하지 않고 파일명이나 `character`를 출력 키로 쓴다.
- [assets/style-reference.png](assets/style-reference.png)는 사용자가 승인한 수지 시트이다. **그림체만** 참고하고 수지의 얼굴, 머리 모양, 기울기, 장식을 다른 인물에게 복사하지 않는다.
- 사진에 이미 있는 머리끈 등 헤어스타일을 이루는 작은 요소는 유지할 수 있다. 별도 모자·안경·소품·장식은 추가하지 않는다.

## 제작 흐름

1. 인물 사진과 스타일 참고 시트를 `view_image`로 확인한다. 여러 사람이나 가려진 얼굴 때문에 기준 인물을 정할 수 없을 때만 필요한 사진을 요청한다.
2. [references/layout.md](references/layout.md)의 여백·눈/턱 기준과 [references/prompts.md](references/prompts.md)를 읽고 사진에서 확인한 인물 특징을 넣는다. 상세한 원본 요구사항은 [references/user-spec.md](references/user-spec.md)에 있으며, 이전 머리 전체 크기 가이드보다 현재 눈/턱 기준을 우선한다.
3. **내장 image_gen**으로 neutral 마스터부터 생성한다. 사진은 identity reference, 수지 시트는 style-only reference로 지정하고 `transparent_background: true`를 사용한다. API 키나 별도 CLI를 요구하지 않는다.
4. 마스터의 인물 유사도·그림체·머리만 남았는지와 실제 양옆 여백을 확인한 다음, 동일 마스터를 유지한 표정 5칸 시트를 생성한다. 사진·스타일 시트·neutral 마스터를 각각 역할을 명시해 참조한다. 생성 단계에서는 셀마다 양옆 80px 이상 투명 여백을 목표로 한다. 셀마다 다른 얼굴을 독립 생성하는 방식을 기본으로 삼지 않는다.
5. 원본 생성 이미지와 실제 사용 프롬프트를 워크스페이스에 보관한다. 권장 구조는 `output/characters/<key>/input/`, `prompts/`, `generated/`, `output/`이다. 새 인물 사진은 이 작업의 입력으로만 사용하고 공개 에셋이나 이 스킬에 넣지 않는다.
6. **생성 직후**, 게임용 크롭이나 에셋 교체 전에 아래 스크립트로 실제 여백을 측정·정리한다. 머리가 온전히 있고 간격만 좁으면 `--pad-to-margin`으로 해결하며, 간격만을 이유로 image_gen을 반복 호출하지 않는다. 원본 셀 경계 접촉·겹침·잘린 머리·표정 오류는 image_gen으로 수정하고 재검사한다. 동일 내용 오류 수정이 2회 실패하면 결과와 남은 불일치를 보여 주고 다음 방향을 확인한다. 색상 임계값으로 배경을 지우거나 별도 코드로 얼굴을 그려 해결하지 않는다.

## 분리와 검사

`scripts/prepare_sheet.py`는 생성 도구가 아니다. 내용을 새로 그리지 않고 포맷 정리·분리·검사만 한다. Python과 Pillow가 필요하며, 없다면 사용 가능한 워크스페이스 런타임을 먼저 찾는다.

```sh
python scripts/prepare_sheet.py --input /absolute/path/generated-sheet.png \
  --output /absolute/path/output/characters/key/output --name key --pad-to-margin
```

출력 크기가 정확하지 않은 경우에만 `--normalize`를 붙인다. **각 셀 전체에 공통 배율과 여백을 적용하고 표정별 자동 확대·정렬을 하지 않는다.** 실제 alpha가 없거나 내용이 셀 경계에 닿으면 생성 이미지를 수정한다. 정규화 후 셀마다 보이는 내용(alpha ≥16)의 양옆 여백이 각각 **64px 이상**, 위아래가 각각 **32px 이상**이어야 구조 검사를 통과한다. 이는 생성 목표 80px의 허용 하한이며, 단순히 옆 얼굴이 안 겹치는지만 확인하지 않는다.

### 간격 처리 순서 — 생성 요청만으로 완료 처리하지 않는다

1. 마스터부터 실제 해상도와 alpha 경계를 확인한다. 목표 크기를 실제 출력 크기라고 가정하지 않는다. 마스터의 여백이 좁으면 전체 이미지 균일 축소·패딩 후 다음 참조로 쓴다.
2. 생성 시트의 5개 머리가 온전히 있는지 `view_image`로 확인한다. 인접 머리의 머리카락·눈물이 섞이면 먼저 image_gen으로 복구한다.
3. 크기가 다르면 `--normalize`를 추가하고, **항상 `--pad-to-margin`**으로 포장·검사한다. 원본 셀 경계 오류가 있으면 패딩을 적용하지 않으며 실패가 유지된다.
4. 간격만 좁으면 모든 셀의 가장 큰 돌출 범위에서 **공통 배율 하나**를 정해 셀 전체에 같은 축소와 패딩을 적용한다. 고정 셀 중심을 쓰고 표정별 bbox로 각각 크롭·확대·재정렬하지 않는다. 충분한 간격이면 변환하지 않는다.
5. `qa-report.json`의 `common_margin_padding`, 셀별 `transparent_margins_px`, `errors`를 확인한다. 최종 목표는 양옆 80px 이상, 위아래 64px 이상이다. 인접 간격은 왼쪽 셀 right + 오른쪽 셀 left로 확인하며 최소160px이 목표다. 첫·마지막의 바깥 여백도 포함한다.
6. 오류 0개와 수동 검토 후에만 런타임을 만든다. 제작 여백 때문에 게임 얼굴까지 작게 유지하지 않는다. 최종 런타임의 눈/턱 좌표로 크기를 맞춘다.

패딩은 원본 alpha를 유지하는 포맷 정리이며 잘린 머리카락을 복구하지 않는다. 목·턱·머리카락 삭제로 여백을 만들거나, 실패를 숨기려고 셀 구분선·통과 하한을 임의로 바꾸지 않는다.

출력: `character_expression_sheet.png`, `neutral.png`, `happy.png`, `angry.png`, `surprised.png`, `crying.png`, `overlay.png`, `qa-contact-sheet.png`, `manifest.json`, `qa-report.json`. 게임용 WebP도 필요하면 `--webp`를 추가한다. 기존 결과는 덮어쓰지 않고 새 디렉터리를 쓴다. 사용자가 덮어쓰기를 요청한 경우에만 `--force`를 사용한다.

## 확인 기준

- 동일 인물의 표정 5개, 정확한 순서와 명확한 감정인가?
- 머리 실루엣·귀·턱·눈높이·코·중심·크기·각도가 유지되는가?
- 목·몸·글자·소품이 없고 실제 투명 배경인가?
- 머리카락과 눈물이 셀을 침범하거나 가장자리에서 잘리지 않는가?
- 양옆·위아래 투명 여백 하한을 모든 셀에서 만족하는가?
- 다른 캐릭터와 나란히 놓았을 때 눈 중심선–턱끝 거리가 비슷한가? 머리카락 길이 때문에 얼굴 피부 부분이 작아지지 않았는가?

프로그램은 alpha와 경계·실루엣 통계만 검사한다. **인물 유사도, 표정, 눈·턱의 정확한 위치, 목 유무를 자동 판정했다고 말하지 않는다.** 모델의 픽셀 수준 일관성도 보장하지 않는다. 경고가 있으면 개별 프레임과 오버레이를 확인해 판단한다.

## times-games 연결

기본 범위는 에셋 제작이다. 적용을 요청받았을 때만 게임에 연결한다. 현재 캐릭터나 `public/core/maker.js`의 브라우저 내 사진 3장 처리 기능을 자동 교체하지 않는다.

- 현재 `public/core/character.js`의 5번째 표정 키는 `sad`: **crying = sad 슬롯(index 4)** 으로 연결하며 API 이름을 바꾸지 않는다.
- 스타일 참고 원본은 **2203×714**로, 폭이 5로 나누어떨어지지 않는다. 그림체 참고용이며 제작 규격이나 자동 크롭 기준이 아니다.
- 512×960 프레임은 현재 프리셋과 비율이 다르다. WebP 변환만으로 기존 `RIGS`의 얼굴·모자·안경 위치가 맞는 것은 아니다. 새 프레임 비율과 앵커를 정하고 다섯 표정, 기본 티셔츠, 모자·안경을 실제 렌더러로 확인한다.
- 게임용 크롭·패딩을 먼저 확정하고, 그 **최종 런타임 neutral 셀**의 양쪽 눈 중심과 턱끝을 사람이 확인해 기록한다. 승인된 수지의 같은 기준과 비교해 캐릭터마다 공통 배율 하나를 정하며, 같은 캐릭터의 5개 표정에는 동일하게 적용한다. 머리 전체 alpha bbox를 80%로 채우는 방식만으로 얼굴 크기를 확정하지 않는다.
- [scripts/fit_face.py](scripts/fit_face.py)는 수동으로 확인한 좌표와 기준 캐릭터의 렌더링 값으로 `RIGS` 후보를 계산한다. 좌표를 자동 검출하거나 얼굴을 변형하지 않는다. 사용법·좌표 형식은 [references/layout.md](references/layout.md)에 있다. 안경은 눈 중심선, 모자·핀은 해당 머리카락 위치에 별도로 맞춘다.
- 리뷰 전에 원래 캐릭터를 덮어쓰거나 커밋·푸시하지 않는다.

완료 시 결과 파일, 도구, 프롬프트, 통과한 검사와 남은 경고를 알려 준다.
